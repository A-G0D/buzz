# Writing map

Match the output to its reader and intended use. Reuse the user's terminology,
separate confirmed facts from recommendations, cite sourced claims, and preserve
important uncertainty. For a document or deliverable, inspect the available
format-specific skill before drafting; load it only when it applies to the
requested artifact and its render/verification workflow is available.

## Skill route

- Check the current harness's installed skill names and descriptions first.
- Prefer an existing skill for a concrete artifact format or repeatable editorial
  procedure; do not import broad "writing" packs by default.
- If no relevant skill is available, write directly and keep the result
  reviewable. A new skill needs a repeated procedure and a with/without
  comparison, not merely a useful prompt.
- Imported or generated skills remain proposals until the configured local
  workflow accepts them; retain provenance and an undo path.
